# Actualización a Gemini 3.8 Flash

Implementación local sobre `codex/team-profile-permissions`. Este cambio todavía no está desplegado ni se ha probado con la clave real de Google.

## Modelo y compatibilidad

El identificador oficial es `gemini-3.8-flash`; Google documenta soporte de texto y salidas estructuradas en la [ficha del modelo](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash). La [guía de migración](https://ai.google.dev/gemini-api/docs/latest-model) requiere retirar los parámetros de muestreo anteriores. La petición conserva el esquema JSON y el límite de salida, pero deja de enviar `temperature`; tampoco envía `topP`, `topK`, `candidateCount` ni un presupuesto de razonamiento antiguo.

Google publica un nivel gratuito para las llamadas Standard en su [tabla de precios](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.8-flash). Eso no acredita la cuota o facturación de una cuenta concreta. No se cambian planes, claves ni límites de uso de la aplicación; las pruebas de esta entrega no consumen generación real.

## Corrección aplicada

- Catálogo de Gemini, modelo predeterminado y datos iniciales actualizados a 3.8 Flash.
- Una función compartida valida modelos por proveedor. Los valores antiguos `gemini-2.5-pro` y `gemini-2.5-flash`, incluidos los que siguen guardados en estructuras, ajustes o trabajos pendientes, se resuelven a 3.8 al generar. Se admite el prefijo `models/`.
- Al cambiar de proveedor, el formulario elige un modelo válido para ese proveedor. El servidor aplica la misma regla: una estructura de Claude no impone su modelo cuando se solicita Gemini. Esta combinación se reprodujo con una prueba; no se inspeccionó el trabajo real de la captura para atribuirle una causa definitiva.
- Orden de selección: modelo explícito válido, modelo de la estructura si corresponde al proveedor, ajuste de ese proveedor y predeterminado del catálogo. Una selección explícita incompatible se rechaza antes de crear el trabajo y reservar cuota.
- Ajustes muestra 3.8 aunque conserve un valor anterior en DB. Guardar Ajustes persiste el nuevo identificador con auditoría. Las lecturas no escriben ni alteran el historial de guiones.
- La comprobación de clave de Gemini consulta los metadatos del modelo, sin generar tokens ni afirmar que conoce el saldo. Usa el valor actual del formulario, no el que había al abrir la página.
- Los fallos 400 de configuración y 5xx del proveedor ya no se confunden con un modelo inexistente. El texto `generateContent` tampoco se interpreta como una limitación de peticiones por contener `rate`.

## Validación

- `npm test`: 47 pruebas, incluyendo nueve casos nuevos de modelo, selección, compatibilidad, configuración del SDK y errores. Las llamadas externas están simuladas.
- `node scripts/test-postgres.mjs scalability consistency`: 28 pruebas con PostgreSQL local; comprueban que la cola admite 3.8 y valores heredados, rechaza el proveedor equivocado y conserva límites, idempotencia y auditoría.
- `npm run typecheck`, `npm run lint` y `npm run build`: comprobaciones de compilación. Lint conserva avisos anteriores.
- `npm run test:workflow`: ejecutor local y navegador con claves ficticias. Recorre los pasos del generador, alterna Claude/Gemini, verifica el identificador mostrado y comprueba la lectura de ajustes antiguos. La respuesta del trabajo de prueba ya está guardada; no llama al proveedor de IA.

## Activación

No hay una migración SQL nueva para Gemini. El despliegue debe incluir estos cambios de catálogo y de petición: cambiar únicamente un texto en Ajustes no actualiza la versión publicada del servidor.

La rama también contiene los perfiles de equipo, cuya activación tiene su propio [procedimiento de Neon y Vercel](perfiles-permisos-2026-09-09.md). Al publicar esta rama completa se deben respetar esos pasos.
